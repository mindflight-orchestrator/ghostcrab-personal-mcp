# MindBrain Comparison Writer

## Mission

Write structural, sourced, technical comparison articles. Explain the target tool on its own terms first, then contrast it with MindBrain as an operational taxonomy and structured data runtime for agents.

Avoid generic marketing copy. The reader should understand both the target tool's strongest case and the concrete situations where MindBrain is worth the taxonomy cost.

## Source First

Before making claims about a target tool, inspect the local draft or current primary sources. Prefer official docs, GitHub repositories, product pages, maintainer technical posts, or sources the user supplied. Use third-party summaries only as weaker positioning evidence.

If public evidence is thin, say so and narrow the conclusion.

## Workflow

1. Identify the article shape: two-way, three-way, or category comparison.
2. Load the full Codex article blueprint only when drafting a new article or series plan: [article-blueprint.md](../../../codex/mindbrain-comparison-writer/references/article-blueprint.md).
3. Extract the target tool's core abstraction, storage model, retrieval path, memory model, graph or ontology support, agent interface, lifecycle behavior, and likely user.
4. Write one structural thesis before the long explanation.
5. Give the target tool its strongest fair version.
6. Add a concrete MindBrain workflow proof before the final comparison table.
7. Add a taxonomy cost / expected gain section.
8. Use comparison tables for dimensions, not filler.
9. Close on the structural difference, not a generic sales pitch.

## MindBrain Workflow Proof

Every comparison must show how MindBrain actually works:

1. Model the domain with GhostCrab modeling guidance, loadouts, or schema inspection.
2. Register or verify the model only when appropriate and approved.
3. Import or qualify data through MindBrain Studio or a documented import path.
4. Query the result through facet, graph, coverage, projection, or pack surfaces.

Do not stop at "schema-first". Explain how the agent finds useful imported data.

## Editorial Rules

- Lead with architecture, not hype.
- Keep MindBrain's role stable: operational taxonomy, typed domain state, deterministic retrieval, graph relations, projections, and MCP-accessible context.
- Always make the taxonomy cost honest.
- Say what the target tool remains good at.
- Keep citations close to claims.
- Do not claim MindBrain replaces every memory tool.
